Duplicate Ticket Detection Model

Jira ticket volume was growing, and duplicates meant the team worked the same problem twice. I built a model to catch them.

Problem

Jira had a growing volume of duplicate tickets. A duplicate is pure redundancy — the same problem gets picked up, worked and resolved more than once — and the cost of that scales with ticket volume, which was going up.

Approach

I built a model in Python to detect duplicate tickets, developing it with Cursor.

This ran against internal Jira data at Crimson Interactive, so there is no repository or ticket set to link to here. Happy to talk through how it works in a conversation.

Outcome

  • Caught 24% of duplicate tickets Roughly a quarter of the duplicates surfaced before the team spent a second round of effort on them.

Tech used

  • Python
  • Cursor
